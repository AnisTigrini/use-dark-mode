Dark mode for React, done right.

A maintained fork of use-dark-mode by Donavon West. The original still gets thousands of downloads a week, but it hasn't been released since 2019, can't be installed on React 17+ without --legacy-peer-deps, and breaks with server rendering. This fork fixes those problems and simplifies the API. All credit for the original design goes to Donavon and its contributors.

Quick start

import useDarkMode from 'use-dark-mode-v2';

function ThemeToggle() {
  const darkMode = useDarkMode();

  return (
    <button onClick={darkMode.toggle}>
      {darkMode.isDarkModeEnabled ? '☀ Light' : '☾ Dark'}
    </button>
  );
}

The hook adds a dark-mode or light-mode class to <body>. Style from there:

body.light-mode { background: #fff;    color: #333; }
body.dark-mode  { background: #1a1919; color: #999; }

Prefer to handle it yourself (CSS variables, a theme provider…)? Pass an onChange callback instead. To avoid a flash of the wrong theme on load, add the no-flash script.

What this fork fixes

  • React 17, 18 and 19

    The original only allowed React 16, so npm refused to install it on newer versions.

    #68 · #70 · #96

  • No hydration errors in Next.js

    The first render now matches the server, and the real value is applied right after hydration: no errors, no flash, no two-click toggle.

    #83 · #55 · #66 · #80

  • The user's choice is respected

    Nothing is saved until the user picks a mode, so visitors who never do keep following their OS theme. Once they pick, OS changes no longer override them.

    #52

  • Works with Vite and modern bundlers

    The original used Node's global, which doesn't exist in browsers.

    #91

  • No abandoned dependencies

    use-persisted-state and @use-it/event-listener are replaced by built-in code. The only dependency is React's official use-sync-external-store shim.

  • Doesn't crash without storage

    In Safari private mode, with a full quota or blocked cookies, the setting is kept in memory for the session instead. Uses the current media query API, with a fallback for Safari < 14.

Migrating from use-dark-mode

npm uninstall use-dark-mode
npm i use-dark-mode-v2

Then change your imports to import useDarkMode from 'use-dark-mode-v2' and update the call and what it returns:

use-dark-modeuse-dark-mode-v2
useDarkMode(initialState, config)useDarkMode(config)
darkMode.valuedarkMode.isDarkModeEnabled
darkMode.enable()darkMode.set(true)
darkMode.disable()darkMode.set(false)
darkMode.toggle()darkMode.toggle() (unchanged)

initialState was only used in browsers without an OS theme setting, so dropping it changes nothing for most apps. If you meant it as "start dark", pass { defaultMode: 'dark' }.

The other options and the default storageKey are unchanged, so your users keep their saved preference. Two behaviours changed on purpose:

  • The initial value is no longer written to storage on first render, only when the user picks a mode.
  • Once the user has picked a mode, changing the OS theme no longer overrides it. Call reset() to go back to the default mode.

API

const { isDarkModeEnabled, toggle, set, reset } = useDarkMode(config);

How the value is chosen

  1. The user's saved choice, if they've made one.
  2. Otherwise defaultMode. With 'system' (the default) that's the OS preference (prefers-color-scheme), updated live. It's light while the OS preference is unknown, during server rendering and hydration. With 'dark' or 'light', the OS is ignored.

Returns

PropertyDescription
isDarkModeEnabledtrue when dark mode is on.
toggle()Flip the current mode and save it as the user's choice.
set(isDarkModeEnabled)Turn dark mode on (true) or off (false) and save it as the user's choice. Use it for explicit Light / Dark buttons or to apply a preference stored on the user's account.
reset()Forget the user's choice and go back to defaultMode. With the default 'system', that's the "System" option of a Light / Dark / System picker.

toggle and reset take no arguments, so you can pass them straight to onClick. Wrap set: onClick={() => darkMode.set(true)}.

Server rendering & preventing the flash

React only runs after the page has loaded, so a saved dark-mode preference would otherwise show a flash of light mode first. Add this tiny script as the first thing inside <body> so the right class is there before the first paint. If you changed storageKey, defaultMode or the class names, change them here too. 

<script>
(function () {
  var storageKey = 'darkMode';
  var classNameDark = 'dark-mode';
  var classNameLight = 'light-mode';
  var defaultMode = 'system'; // or 'dark' / 'light'
  var dark;
  try {
    var stored = localStorage.getItem(storageKey);
    if (stored !== null) dark = JSON.parse(stored);
  } catch (e) {}
  if (typeof dark !== 'boolean') {
    dark = defaultMode === 'system'
      ? !!(window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)').matches)
      : defaultMode === 'dark';
  }
  document.body.classList.add(dark ? classNameDark : classNameLight);
  document.body.classList.remove(dark ? classNameLight : classNameDark);
})();
</script>

It only reads storage, never writes it, so visitors who haven't picked a mode keep getting the default mode.

Next.js App Router

Inline the script in your root layout. suppressHydrationWarning tells React the class on <body> was changed on purpose before hydration.

// app/layout.js
const noFlash = `/* the script above, without the <script> tags */`;

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body suppressHydrationWarning>
        <script dangerouslySetInnerHTML={{ __html: noFlash }} />
        {children}
      </body>
    </html>
  );
}

Components that call useDarkMode must be Client Components ('use client').

Next.js Pages Router

// pages/_document.js
import { Html, Head, Main, NextScript } from 'next/document';

const noFlash = `/* the script above, without the <script> tags */`;

export default function Document() {
  return (
    <Html>
      <Head />
      <body suppressHydrationWarning>
        <script dangerouslySetInnerHTML={{ __html: noFlash }} />
        <Main />
        <NextScript />
      </body>
    </Html>
  );
}

Gatsby

Inject the script at the start of <body> from gatsby-ssr.js:

// gatsby-ssr.js
import * as React from 'react';

const noFlash = `/* the script above, without the <script> tags */`;

export const onRenderBody = ({ setPreBodyComponents }) => {
  setPreBodyComponents([
    <script key="no-flash" dangerouslySetInnerHTML={{ __html: noFlash }} />,
  ]);
};

Don't use gatsby-plugin-use-dark-mode with this package: it's archived, installs the original use-dark-mode, and its script saves the OS theme as if the user had chosen it.

Vite, Create React App, plain HTML

Paste the script right after <body> in your index.html:

<body>
  <script>/* the script above */</script>
  <div id="root"></div>
  <script type="module" src="/src/main.jsx"></script>
</body>
